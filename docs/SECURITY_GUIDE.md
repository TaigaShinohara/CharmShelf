# CharmShelf セキュリティ開発ガイド

脆弱性の報告窓口と公開範囲は[SECURITY.md](../SECURITY.md)を参照してください。この文書は開発時に維持する境界をまとめます。

## データを扱う変更

- ライブラリのファイルと管理情報、外部にある元ファイルを区別します。削除・解除・復元の対象と確定前の状態を確認してください。
- 操作失敗を表面化し、キャンセル・部分失敗・再実行で既存データを壊さないことを確認します。読み取りや移行の失敗を、データの初期化で回避しないでください。
- アプリロックや非表示機能は画面へのアクセス・表示を制限する機能です。ファイルの暗号化や、すべてのOSアクセス経路からの保護を保証しません。
- ライブラリのバックアップは暗号化されず、非表示・アーカイブ・ごみ箱の内容も含みます。保存先と含まれる内容を確認できる状態を保ちます。詳しくは[プライバシーポリシー](PRIVACY_POLICY.md)を確認してください。

## 認証情報とログ

通常のDebug開発にAPIキーや配布署名は必要ありません。任意の配布設定は[auth/README.md](../auth/README.md)に分離しています。秘密値、個人メディア、端末内の実パス、未加工の診断ログをIssueやPRへ添付しないでください。

実行時の認証情報は既存の[SecureStorageService](../lib/core/services/secure_storage_service.dart)を確認し、用途とOSごとの保存・移行条件に従って扱います。共有設定やソースへ秘密値を保存しないでください。Androidの移行処理は[ローカルパッチの説明](../patches/flutter_secure_storage/README.patch.md)を参照してください。

診断処理を変える場合は[ロガー](../lib/core/logger/app_logger.dart)と[クラッシュ情報の秘匿処理](../lib/core/error/crash_report_privacy.dart)を確認し、合成データで回帰を確認します。ログ本文に利用者の情報が残らないことを、文字列の見た目だけで判断しないでください。

## 検証と依存関係

[セットアップガイド](SETUP_GUIDE.md)の静的解析・監査に加え、変更に応じた権限拒否、キャンセル、部分失敗、再試行の検証を行います。ホストテストの成功と実端末の動作確認は区別して報告してください。

現在ツリーの混入確認は `python3 scripts/maintenance/check_private_content.py --sources-only` で行えます。検査には対象範囲と検出規則の限界があり、すべての秘密情報や安全性を証明するものではありません。

依存パッケージの更新では[パッチ台帳](DEPENDENCY_OVERRIDES.md)、元ライセンス、[native由来情報](NATIVE_PROVENANCE.md)を維持してください。
